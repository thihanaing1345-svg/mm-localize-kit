# Roadmap

## 30-day development roadmap

| Period | Goal | Deliverables |
| --- | --- | --- |
| Week 1 | Stabilize the MVP | Confirm API names, add tests for all utilities, improve README examples, and publish `0.1.0-alpha`. |
| Week 2 | Improve correctness | Review phone/operator rules, expand Unicode normalization tests, document Zawgyi detector limitations, and add benchmark fixtures. |
| Week 3 | Strengthen data and CLI | Expand township dataset with provenance, add CSV/JSON CLI input options, and add search normalization recipes. |
| Week 4 | Prepare first public release | Publish `0.1.0`, create docs site outline, add good-first-issue labels, and collect feedback from Myanmar developers. |

## 90-day open-source growth roadmap

| Month | Focus | Success signals |
| --- | --- | --- |
| Month 1 | Release and validation | First npm release, passing CI, public roadmap, early community feedback, and documented limitations. |
| Month 2 | Community and integrations | More examples, Next.js guide, React Hook Form guide, dataset provenance, and first outside contribution if possible. |
| Month 3 | Adoption evidence | npm download trend, GitHub issues from real users, testimonials or use-case notes, improved benchmarks, and a clearer Codex application case. |

## Milestone for applying to OpenAI Codex for Open Source

The best time to apply is after the project has public releases, several weeks of maintenance activity, real issue discussions, npm downloads, and at least a few credible users or contributors. If applying earlier, the application should be transparent that the repository is new and should emphasize ecosystem need rather than adoption metrics.
