# Ethical Adoption Plan

## Getting real users

The project should earn users by solving real problems. The maintainer should share runnable examples, publish a clear npm package, write practical guides, and ask Myanmar developers to test specific workflows such as phone validation, product search, online shop price formatting, and spreadsheet cleanup.

## Collecting feedback

Feedback should be collected through GitHub issues, discussions, short community posts, and direct developer interviews when appropriate. Each piece of feedback should be converted into a public issue or roadmap item if the contributor agrees. Private user data, production exports, and customer records should never be requested.

## Encouraging GitHub stars without spam

It is acceptable to say, “If this helps your Myanmar-language project, a GitHub star helps others discover it.” It is not acceptable to buy stars, automate stars, pressure people, create fake accounts, or imply that stars are required for support.

## Tracking npm downloads

Track npm downloads using npm package stats, GitHub repository traffic, and issue activity. These metrics should be described honestly. Do not inflate numbers, combine unrelated packages, or claim users that have not consented to being named.

## Responsible OpenAI Codex use

Codex should be used to improve tests, documentation, issue triage, security review, and maintenance automation. It should not be used to generate fake community activity or misleading adoption evidence.
