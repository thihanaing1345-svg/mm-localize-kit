# OpenAI Codex for Open Source Application Draft

This document provides honest draft answers and timing guidance for a future OpenAI Codex for Open Source application. The project should not imply adoption, npm downloads, GitHub stars, or production users that do not yet exist.

## Readiness assessment

**mm-localize-kit** is a legitimate open-source project idea because Myanmar-language developers face recurring localization, validation, encoding, formatting, search, and data-cleaning problems. The repository now contains working TypeScript utilities, tests, examples, documentation, community files, and a roadmap.

However, a brand-new repository should not be presented as already established. The stronger path is to publish v0.1.0, invite real usage, collect issue reports, improve correctness, and apply after there is visible maintenance history and evidence of community value.

## Suggested milestone before applying

| Milestone | Evidence to collect |
| --- | --- |
| v0.1.0 published | Public npm package, release notes, passing CI, documented examples |
| First real feedback | GitHub issues, discussions, or pull requests from Myanmar developers |
| Maintenance activity | Several commits after launch, triaged issues, changelog updates |
| Adoption signals | Honest npm download counts, stars, forks, mentions, or integration examples |
| Data quality | Reviewed township data provenance and test fixtures from real edge cases |

## Draft answer: Why does this repository qualify?

This repository addresses recurring Myanmar localization problems for web and app developers: Unicode/Zawgyi handling, phone validation, MMK formatting, numerals, dates, search normalization, form helpers, datasets, and CLI cleanup. It is open source, tested, documented, and maintained honestly as an early project. I will apply after v0.1.0 has real usage and feedback.

## Draft answer: How will API credits be used?

Credits would be used to improve maintainability, not to replace community review: generating test fixtures, checking edge cases, drafting docs, improving CLI behavior, reviewing TypeScript changes, and helping triage issues. AI output will be reviewed by maintainers, and localization/data changes will require tests and provenance before merge.
